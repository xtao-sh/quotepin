# 示例工作区

一份可以直接载入的演示内容：两个分组、四个项目（含一个子项目）、九份文档和十四条批注。
用来在不动你自己文件的前提下，把这个应用的主要用法走一遍。

课程、人物和数据全部虚构，每份 PDF 页脚都写着这一点。

## 载入

先启动批注工作台（或 `npm run dev`），然后：

```bash
npm run examples
```

脚本会把示例文件复制到 `~/Documents/批注工作台示例/`，再从那里导入。**不是**从仓库里直接导入——
文档会记住自己的原始路径，绑在仓库检出目录上没有意义，而且刷新演示需要覆盖源文件。

想放到别处：

```bash
REVIEW_EXAMPLES_DIR=~/Desktop/示例 npm run examples
```

应用如果监听在别的端口（4520 被占用时 Electron 会退到随机端口），用 `REVIEW_API_URL` 指定：

```bash
REVIEW_API_URL=http://127.0.0.1:4530 npm run examples
```

## 载入后先试这三件事

**一、刷新与重新定位。** 打开「第4讲讲义.pdf」，顶栏会显示「有新版本」。点刷新，然后看两条文字批注：

- 引用「谁被系统性地漏掉了」的那条：第二版在它前面插了一整页，原文整体后移，但一个字没改，
  所以这条批注被重新定位到新的一页上，仍然对得上。
- 引用「下周三 18:00」的那条：第二版把截止时间改成了下周五 12:00，原文不在了，这条会被标成失配，
  由你决定它还算不算数。

这是刷新和重新导入的区别：批注、版本历史和文档身份都保留着，第一版随时可以恢复。

**二、跨文档的矛盾。** 搜「周」或者「字以内」：

- 课程大纲说「课程共 12 周」，课程日历排到第 14 周。
- 课程大纲说「正文 300 字以内」，期末项目评分标准说 500 字。

**三、清理重复文档。**「示例课程」和「待归档收件箱」里是同一份大纲，一份带批注一份没有。
菜单里选「清理重复文档」，它会说明删掉哪一份会连带删掉多少条批注。

另外「第3讲讲义.pdf」已经归档，收在文档列表底部的历史区里：原文件、批注和版本历史都在，
只清掉了可以重新生成的渲染缓存。

## 目录里有什么

| 文件 | 用来演示 |
| --- | --- |
| `课程大纲.pdf` | 点标、框选、文字批注、整页备注四种类型同处一档；「已解决」默认不导出 |
| `课程日历.csv` | CSV 进入文本层，可选中可引用 |
| `第3讲讲义.pdf` | 归档 |
| `第4讲讲义.pdf` | 刷新、重新定位、版本回滚 |
| `第4讲讲义-v2.pdf` | 上面那份的第二版，载入时会替换掉源文件；本身不进工作区 |
| `讲义修订说明.md` | Markdown 文本层 |
| `期末项目评分标准.txt` | 纯文本文本层 |
| `抽样示意图.png` | 图片只能点标和框选；装了 `chi_sim` 才能按页 OCR |
| `读书笔记-课堂参与度.txt` | 第二个分组存在的理由 |

`manifest.json` 定义了上面这套结构和全部批注，`generate.py` 用来重新生成 PDF 和 PNG。

## 关于这些 PDF

中文用 reportlab 的 `STSong-Light`，这是 Adobe 标准 CJK CID 字体，PDF 里**只引用不嵌入**。
好处是每份讲义只有几 KB，仓库里也不需要放字体文件；代价是 PDF 不自包含——阅读器得自己有中文字体。
macOS 和装了中文字体的 Linux 都正常，纯净容器里会显示空白。

这只影响这几份示例文档。你自己的文件不受影响。

改完内容重新生成：

```bash
python3 examples/generate.py
```

## 清理

示例内容和你的文档在应用里是一样的东西，所以删除方式也一样：在应用里删掉这四个项目，
再删掉 `~/Documents/批注工作台示例/` 这个文件夹。
